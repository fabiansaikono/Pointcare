## v3.3 localization fix

This pack fixes the v3.2 issue where many non-numeric answer options had only one `<display>` value, often English. Importers must now select `answer/display[@locale=currentLocale]` for UI and use `answer/@value` for correctness. Fallback order: selected locale, `nl-BE`, `en-US`, first display.
